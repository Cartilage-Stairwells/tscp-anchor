# Errata

This erratum accompanies the versioned drafts in this directory. It does not replace them, and no manuscript copy has been altered: each version remains the record of what that version said. Everything below was established against the implementation at the basis commit above.

## E1. Section 4.4: finding status is as-of-audit, not current

Section 4.4 records the audit's findings with the dispositions assigned at audit time. Five of those findings have since been closed in code, and the section carries no resolution pointers, so a reader checking the paper against the repository finds five findings that read as open. The finding text is preserved as recorded; current status is added here.

| Finding | Recorded at audit | Current code status | Resolution |
|---|---|---|---|
| 29 — serialization omits Merkle openings | Documented with warning; digest computed over an incomplete representation | `SerializableFriProof` no longer exists in the workspace. The v1 encoding binds every verification-relevant field, including all Merkle openings. On the recorded 256-evaluation test vector, the proof representation grew from 2,148 B (incomplete) to 72,266 B (complete); this is a measurement of that vector, not a general claim about proof sizes. | PR #53 |
| 30 — debug formatting of roots | Documented with warning; `{:?}` produces a non-reproducible digest | Neither digest input contains `{:?}`; both hash canonical bytes. The one remaining `{:?}` in the bridge is inside a comment naming the pre-v1 format, not in a digest path. The expression-depth limit of 100 described in this finding is present at `crates/prover-server/src/poly_ir.rs:47-51`. | PR #53 |
| 32 — additive shift with unchecked cast | Documented with TODO; additive shift called the same issue as Finding 23 | The integer-domain machinery retains additive shift semantics. This is a local convention for that domain, not a resolution of the general algebraic shift contract. The cast is checked (`u32::try_from`, `InvalidDeepPoint` on overflow). | PR #49 (cast half); issue #36 (shift-convention ruling) |
| 33 — naive Lagrange interpolation is O(n²) | Documented; production should use FFT-based interpolation | The DEEP-ALI quotient-construction implementation uses two-adic subgroup interpolation via an inverse FFT, replacing the former quadratic interpolation approach. The naive implementation remains as an independent test oracle and in the dormant verification machinery. | PR #54 |
| 35 — accumulator not bound to the Fiat-Shamir transcript | Documented with warning; a malicious prover could reset the accumulator | Binding is implemented: each successful consume absorbs the round, bits consumed and bits remaining into the challenger, a failed consume binds nothing, and the encoding is checked. The binding is latent. | PR #50 |

**Notes on scope, per finding.** Two rows above carry a distinction that should not be collapsed:

- **Finding 32.** The broader additive-versus-multiplicative decision remains deferred, pending the evaluation-domain, interpolation-basis, and verifier-equation contract. Retaining additive semantics in the integer-domain machinery does not settle it. PR #49 and the issue #36 ruling are separate resolutions: #49 fixed the cast, and #36 ruled on the convention for one domain.
- **Finding 33.** This is a structural complexity improvement, not evidence of production-serving integration and not a measured benchmark result. The quotient-construction code the change applies to has no production caller.

**Activation boundary.** Closing a finding in code is not the same as activating a component in production, and the table above should not be read as claiming the latter:

- Findings 29 and 30: canonical proof bytes exist and are tested, but no served endpoint consumes them. The only served route is `POST /prove/sumcheck`.
- Finding 32: the corrected function is on no live path, and the convention question stands deferred as described above.
- Finding 33: the complexity change is structural and unmeasured. The naive implementation still executes inside the dormant verification machinery.
- Finding 35: **the described accumulator-reset attack has no reachable production path through the current serving architecture, because the accumulator has no production constructor and the batch verifier has no production callers.** This states the observed code boundary; it does not claim the vulnerability has been eliminated from every possible future integration.

## E2. Section 3.3.3: scope of the OWSL content hash

The section currently states:

> The OWSL status includes a SHA-256 content hash over all status fields, verified by the Rust bridge on read. This prevents a compromised daemon from falsifying its own health reports without detection.

The final sentence should read:

> The content hash detects accidental corruption or inconsistency between published health-report fields and their digest. Separate status-validation logic is responsible for detecting partial publication and stale reports. Because the daemon produces both the report fields and their hash, this mechanism does not independently establish the truthfulness of a potentially compromised daemon.

**Why the boundary sits where it does.** The properties are carried by different mechanisms, and only the first is a property of the hash:

- **Integrity.** The daemon computes the digest over the object it publishes and the bridge recomputes it from those same fields, so a mismatch indicates corruption or internal inconsistency.
- **Freshness.** Status reads are rejected beyond a maximum age (60 seconds in the current implementation).
- **Atomic publication.** Status is written to a temporary file and renamed into place, so a reader does not observe a partially written file.
- **Minimum-state validation.** The verification gate requires positive remaining bits. A separate health predicate additionally requires a positive frame count, but that predicate currently has no call sites. Neither check is part of the content hash.
- **Authentication.** A producer that authors both the fields and their hash yields a self-consistent pair. The hash therefore cannot establish that a compromised daemon is telling the truth.

The section's surrounding scoping — that entropy health is a defense against degraded execution environments and not a proof that low entropy breaks Fiat-Shamir soundness — is unaffected and stands.
